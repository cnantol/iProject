## 5. 已实现并验证的核心能力

- 23 张表按 schema.sql 建库；单管理员 JWT 登录（7 天）、改密、审计日志。
- 9 步订单工作流 + `lost_closed` 只读终点：
  `customer_info → proposal(可跳过) → quotation → approval_pending → bid_decision → finance → shipping_invoicing(并行) → commission → closed`
- 状态流转全部条件 UPDATE，并发冲突返回 409；闭环后第 9 步不再显示“进行中”。
- 价格决策：框架协议价 / 指导价（实付比例）/ 手工价，标准物料描述自动回退指导价。
- 方案：版本、选型、附件、Excel 批量导入、仅物料号粘贴录入、批量保存。
- 报价：多轮次（草稿可删除，已提交/被审批引用禁删）、价格即时合计、批量导入/粘贴、从方案同步（可选版本，仅同步物料号+数量，标准自动描述/价格，非标保留类型与描述，手工价保留）、PDF 导出（带 token 下载）。
- 并行审批：双线同一轮次；驳回后全部审批状态重置（superseded，保留驳回记录），重新提交须双线重新审批；审批历史汇总表。
- 财务：SO 失焦自动保存 + 添加 PO 自动先存 SO；SO/PO 保存状态指示灯；PO 可编辑。
- 发货/开票：批次累计 100% 才可标记发货；开票按 PO、累计≥PO 总额自动 invoiced；两项完成自动推进佣金；页面自动跳转佣金步骤。
- 佣金：Excel 全局匹配（幂等、金额列必选、重复 SO 仅计数）、人工补录、等待清单。
- 看板 / 历史销售 / 待办（月历+四区）/ 基础数据 / 字段管理 / 流程展示配置 / 数据导入（Excel+模板）/ 数据修正 / 软硬重置（JWT 轮换）/ 备份还原 / 应用内定时备份配置 / 报价单式样配置（PDF 生效）。

## 8. 排查/开发注意事项（血泪教训，避免重复踩坑）

- MUI `sx` 中数字间距会乘以主题系数（如 `mt: 15` = 120px），需要精确像素请写字符串 `'15px'`。
- 主题文件里的变量：当前 `md3Theme.js` 是精简版，只有 `mode` 参数，**不要引用不存在的 `dark` 变量**（曾导致全站白屏）。
- `apply_patch` 是原子的：一个 hunk 不匹配会整批失败；多个文件的 hunk 必须按文件内行号顺序排列。
- 步骤组件刷新：订单详情刷新时不要卸载步骤内容（`loading && !detail` 才显示加载圈），否则提示/错误状态会丢失。
- 步骤组件接收的 `order` 必须是合并后的完整详情对象（含 versions/quotations/approvals/pos 等），不能只传 orders 主表行。
- MUI Select 弹层在自动化环境可能打不开，验证时优先用 API 或检查 DOM 文本；下载类 href 需要 `?token=` 或 blob 下载。
- 表单校验与后端一致：金额>0、qty>0、pay_percent∈(0,100]、布尔 0/1；佣金金额列必选。
